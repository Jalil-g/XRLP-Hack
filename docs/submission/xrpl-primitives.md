# Appendix: XRPL primitives we use, where they live, and the devnet proof

Every link opens a validated transaction on XRPL **devnet** (rippled 3.4.1; Vault and Lending aren't enabled on testnet or mainnet).
Every hash comes from our proof docs or PR descriptions; `node docs/submission/check-links.mjs --devnet` checks that, then fetches
each tx and compares its result. Link text is the transaction type, or the **result code** when the point is that the ledger refused.
Code is in `packages/xrpl/src/`.

**Sources** (the Src column): **v2** = [`proof-devnet-2026-10-25-v2.md`](../proof-devnet-2026-10-25-v2.md), the merged `main` run end
to end on 2026-10-25, 00:05–00:40 UTC (PR #126). It's preferred wherever it has the tx. **§1b**, **§2d**, **§2e**, **§3c** = [`xrpl-protocol-notes.md`](../xrpl-protocol-notes.md)
§1b (release path, XRPL-07), §2d (Batch spike, XRPL-13), §2e (atomic escrows in the close path + recovery, XRPL-13b) and §3c (loan default,
XRPL-15), all 2026-10-25. **#121**, **#128** = devnet runs in those PR descriptions on 2026-10-25. **X11** = `packages/xrpl/proof/xrpl-11-devnet-2026-10-25.md`
(the CLI `demo` / `prestage` runs; the M5 run is on merged `main` with the batch close). Nothing here comes from the v1 run
(`proof-devnet-2026-10-24.md`, which used the old signer list).

## Refused before reaching a ledger (no explorer page, by design)

`tef*` and `tem*` results are never applied, so there is nothing to link to; that's why the demo shows `tec` cases.
- SPV master key → `tefMASTER_DISABLED`; 2 of 4 signers → `tefBAD_QUORUM`; the AI's key as a signer → `tefBAD_SIGNATURE` (v2 §4).
  `submitMultisigned()` checks quorum against the on-ledger SignerList before it submits anything.
- `LoanSet` as a Batch inner tx → `temINVALID_INNER_BATCH` on rippled 3.4.1 (§2d).
- Our own refusals, with nothing submitted: `preflightFinish()` (`no_trustline`, `condition_mismatch`, `expired_or_too_close`; v2 §5–6),
  `planLoanClose()` (duplicate or malformed condition, `CancelAfter` not before maturity), and closing before `SubscriptionDate` (`TooSoonError`).

## Not used (yet)

- **Smart Escrows (XLS-100)** would make the suite's result the on-chain release rule. Not on devnet: roadmap.
- **DepositAuth**: left off on purpose. It gives control to the recipient, not to the checks.
